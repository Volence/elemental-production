# v2.1.0 Producer Feedback Batch — Design

Sixteen items from the producers' Discord feedback (DanBuzzBuzz, MetalOBS, Little Joe), triaged
2026-08-15. Owner approved the four open design calls: Final Stats = desk scene with casters;
"IF NEEDED" watermark removed but DECIDER pill/dim kept; image assets committed + bundled;
single v2.1.0 release.

All root causes below were confirmed by read-only investigation against the current tree (0b191bb).

## Bugs

### 1. Map intro stuck on map 1 (single-`current` invariant)
The reported screenshot predates v2.0.2's fix, but a residual defect is real: `setMapStatus` in
`src/pages/MatchHub.jsx:234-237` (the ▶ Play button) sets a map to `current` without demoting the
map that is already `current`. Two `current` maps → `findCurrentMapIndex` (`overlays/theme-helpers.js:132`)
and `maps.find(m => m.status==='current')` (`server/server.js:275`, flythrough/music selection) return
the first forever. In FACEIT mode the poll's forward-only STATUS_RANK merge (`server/server.js:1026-1028`)
makes the stray `current` sticky.
**Fix:** demote any other `current` map (winner→`completed`, else `upcoming`) in `setMapStatus`;
belt-and-braces normalization server-side in `PATCH /api/state`; regression test for
`findCurrentMapIndex` with two `current` maps.

### 2. "Relinquish All" doesn't update team scores
`DELETE /api/overrides` (`server/server.js:1143-1147`) is a pure flag delete — no score recompute, no
`reconcileHeroBans()`, no FACEIT refetch, no `syncToOBS`. Single-override release works because the
client follows it with `POST /api/faceit/refresh` (`src/pages/MatchHub.jsx:124-136`); Relinquish All
(`:139-141`) doesn't. Scores are stored, not derived (`server/state.js:19-20`).
**Fix (server-side so Stream Deck behaves identically):** `DELETE /api/overrides` → clear, then
`reconcileHeroBans()`; if FACEIT match loaded → refetch (extract `POST /api/faceit/refresh` body into
`refreshFromFaceit()`); else derive scores from map winners; then broadcast + `syncToOBS`.
Also fix `server/server.js:1064-1065` (computed score iterates the FACEIT-index array, missing
manually-appended maps' winners).

### 3. Map Pool / Ban Reveal / Flythrough browser sources need manual refresh after OBS restart
`BROWSER_SOURCES` (`server/server.js:2220-2236`) is missing `Map Pool BS` and `Ban Reveal BS`
entirely, and has `Casters Flythrough HUD` (real input name is `...Hud` — case-sensitive). The boot
heal (`setupBrowserSources`, `:2240-2261`) presses refreshnocache on listed sources only. Secondary:
`browserSourcesConfigured = true` latches even when OBS wasn't connected (obs.connect never rejects),
so app-before-OBS means no source setup ever runs.
**Fix:** refresh pass enumerates browser sources from OBS by URL match (`/overlays/`) like
`POST /api/overlays/refresh` already does; latch only on a successful pass; add an `onConnected` hook
in `server/obs.js` (fires on boot connect AND reconnects) that clears `lastSyncedState` and runs
`syncToOBS` + `setupBrowserSources` + `hideAudioSourceVideo`; call `setupBrowserSources` from
`POST /api/obs/connect` too. Regression test: every `/overlays/` browser source in
`data/obs-scene-collection.json` has a URL-seeding entry (or is covered by enumeration).

### 4. Top scene strip cuts off the last scenes
`.scene-toolbar-inner` (`src/index.css:842`) is an overflow-x scroller with the scrollbar hidden and
no wheel handler — overflowed buttons are unreachable. 16 scenes ≈1600px vs ~1116px available at the
default window size.
**Fix:** `flex-wrap: wrap` (+ `row-gap`) so every scene is always one click; add `min-width:0` +
label ellipsis as a guard; add `Map Pool`/`Ban Reveal`/`Casters Flythrough` to `SCENE_ICONS`
(`src/App.jsx:47-50`).

### 5. Ban Reveal red strike lines too blurry
No blur exists — `.v2-ban-art-slash` (`overlays/theme-v2.css:319-322`) uses percentage gradient stops
(46/49/51/54%); on the ~710×680px reveal panel 1% ≈ 9.8px → ~78px soft beam. Crisp at 56px tiles,
mush at reveal scale.
**Fix:** hard px stops via `calc(50% ± Npx)`: 2px dark outline, ~10px solid red core,
`drop-shadow(0 0 5px rgba(255,0,0,.4))` instead of the 30px ramp. Scale core width per tile via a
`--slash-core` CSS var emitted by `banArtTile` (reveal 5px, deck 2px). Keep `hbSlashSweep`
(translate/scale on the gradient parent is safe; no rotated child).

### 6. Ban reveal shows face icons instead of full-body renders
Lookup chain and fallback are correct; the miss is environmental: packaged app sets
`ELEMENTAL_USER_DATA` → `HERO_RENDERS_DIR` = `~/.config/elemental-production/hero-renders`, which is
auto-created empty. The 52 WebP renders live only in the repo's gitignored `data/hero-renders/` and
are not in `package.json` build.files. Dev works; every packaged install falls back to portraits.
**Fix:** un-gitignore `data/hero-renders/` (and `data/map-images/`), add to electron-builder
`extraResources`, seed `userData/hero-renders` + `userData/map-images` in `initUserData()`
(`src/main/index.js`) copying only files not already present (producer drop-ins win). Overlay
hardening: if the OverFast hero entry is missing, fall back to `/hero-renders/<banKey>.webp` directly
(ban key already equals the filename).

### 7. Neon Junction has no picture
`data/map-images/` is empty everywhere (only README committed); all map art is live OverFast CDN, and
OverFast has no Neon Junction screenshot (blank card confirmed structurally: catalog entry exists —
else no card at all — but screenshot is empty/404).
**Fix:** source a high-quality Neon Junction image (≥1200px, target 1920) into
`data/map-images/neon-junction.jpg`, shipped per item 6. Add `.webp` to
`SUPPORTED_MAP_IMAGE_EXTENSIONS` (`server/map-image-resolver.js:19`) for parity with the hero
resolver. `map-pool.html` renders a named placeholder (port `.mp-col-art-placeholder` pattern from
map-pick) instead of a blank card when art is missing.

### 8. Top switcher forgets v2 scenes when app starts before OBS
`src/App.jsx:169-171` falls back to a stale 13-scene pre-v2 list (ProductionControls has the correct
16), and `/api/obs/scenes` is fetched exactly once at mount; nothing re-fetches when the 5s status
poll sees OBS come up. Production tab looks right only because it re-fetches on every tab open.
**Fix:** shared `DEFAULT_SCENES` constant (new `src/lib/scenes.js`, seeded from the canonical order)
imported by both components; re-fetch scenes on `obsConnected` false→true; make `obs.getScenes()`
disconnected path return `{scenes:[], currentScene:''}` (stable shape). Together with item 3's
onConnected hook this removes the "start OBS first" requirement.

### 9. Map pool never updates for Peninsula
Not a name mismatch. `modeTaken` (`overlays/map-pool.html:310-318`) is computed only from pool-member
names — a series map outside the saved pool (Ilios) freezes its whole mode column. Compounding: a
played map that IS in the pool gets no state class at all unless FACEIT provides picker/roundScore.
**Fix:** derive taken modes from the series maps via the catalog (`mapDataByName[normMapName(...)]
.gamemodes`); add an always-visible `.mpo-card-played` state (border + PLAYED tag) for completed
in-pool maps. Also: add `'clash'` to `MODE_ORDER` (map-pool + Settings copies) and normalize the
Settings pool editor's checkbox comparison (King's Row U+2019 latent dup bug).

### 10. King's Row blurry in map pick
`getMapScreenshot` (`overlays/map-pick.html:202-213`) matches by raw lowercase name / hyphen-slug —
fails on OverFast's U+2019 apostrophe → falls through to FACEIT `image_sm`, a 110×55 WebP upscaled
~12×. Identical broken copies in `casters-map-score.html:157` and `casters-lobby.html:174`.
**Fix:** promote `normMapName` into `overlays/theme-helpers.js` (NFD strip + apostrophe fold), use it
in all three scenes (and map-pool's local copy); flip `image: m.imageSm || m.imageLg` →
`m.imageLg || m.imageSm` (`server/server.js:818`, `:1027`); ship a high-res `kings-row.jpg` local
image per item 6/7. Unit tests for the promoted normalizer.

### 11. White text unreadable on bright team colors (yellow/green)
No contrast helper exists for text ON a bright fill (`legibleColor` solves the inverse). Offenders:
gameplay-hud score boxes (`:320-324` + `.hbar-score` white), shared map pips winner fill
(`components-v2.js:385-389`), hero-bans BANNED chip (`:202`), map-pick `.mp-chip-score` (`:292`),
map-pool `.mpo-chip-score` (`:279,:286`).
**Fix:** `textOnColor(hex)` in theme-helpers using WCAG relative luminance (white vs `#0a0c11`,
whichever contrast is higher); private `_textOnColor` copy in components-v2 (it can't require
theme-helpers by design). Apply at the five offender sites. Sweep: wrap remaining raw team-color TEXT
spots (map-pick pick pill, casters-map-score team name/score, casters-scoreboard team headers) in
`legibleColor(color, 0.45)` for consistency. The color picker itself is untouched.

### 12. Manual/scrim needs a per-map score input
`roundScore` is a FACEIT-only opaque display string (`round_stats['Score Summary']`); four overlays
render it; no input exists. The Map Series card in MatchHub renders in all modes.
**Fix:** small text input (placeholder "2-1") in each map card's controls row writing
`maps[i].roundScore` via the existing `PATCH /api/state`; `setOverride('maps')` only in FACEIT mode;
seed `roundScore: null, picker: null` in `addMap` so manual entries match the FACEIT shape. Free
string, never parsed.

### 13. "IF NEEDED" on the decider card
Owner: a decider can be played even when the series is decided (teams may play it out), so the label
is wrong — remove it. Lives at `overlays/map-pick.html:372` (+ CSS `:130-134`).
**Fix (approved):** remove the watermark only; keep the `DECIDER` pill and the subtle dim.

## Features

### 14. Stinger as a real OBS stinger transition (WebM + alpha)
`stinger-transition.html` is static branding (no team colors, no state) — one render serves all
matches. 1.1s, 4 CSS animations, frame fully transparent at end; ~50-60% is full-coverage (transition
point). Machine has ffmpeg n9 (libvpx-vp9 + yuva420p) and headless Chrome 151; the documented capture
recipe is `document.getAnimations()` → pause → scrub `currentTime` per frame (NOT
--virtual-time-budget) with `Emulation.setDefaultBackgroundColorOverride` alpha 0.
**Design:** `scripts/render-stinger.mjs` (CDP over headless Chrome, 60fps × 1.1s ≈ 66 frames + a few
transparent tail pads → ffmpeg `libvpx-vp9 -pix_fmt yuva420p`) → commit `public/stinger-transition.webm`
(~1-3MB). Serve via existing static; Settings gains a "Stinger transition (WebM)" download link +
short OBS how-to (Scene Transitions → + → Stinger; file; Transition Point ≈ 600ms; verified value
stamped by the render script into the docs). The render script is committed + documented so the file
is reproducible; CHANGELOG + README producer notes.

### 15. Final Stats scene (series totals)
Approved layout: desk scene with caster cams, same pattern as Casters Scoreboard. `state.playerStats`
already retains one entry per played map (whole-array replace on every sync), so aggregation is
overlay-side: join per player on `playerId` (fallback nickname), sum kills/deaths/finalBlows/
damageDealt/healingDone, recompute K/D from totals (never average per-map ratios), match round-teams
to team1/team2 by `teamId` vs `state.teams.*.faceitId` (not array index), Tank→Damage→Support order,
per-team totals footer, header = series score + per-map result chips. Manual/scrim → same empty-state
placeholder pattern as casters-scoreboard.
**Registration (Map Pool precedent, complete list):** `overlays/final-stats.html` (generic route
serves it); generator spec + `ensureOverlayScene` + `ensureSceneAudio` + `OVERLAY_SOURCES` +
`CANONICAL_SCENE_ORDER` (insert 'Final Stats' immediately after 'Map Score', before 'Between
Matches'); regenerate both collection JSONs; generator tests; Settings URL
list + Stream Deck list; ProductionControls sceneList fallback + overlayFile + focusConfig (+ thumb
optional); `defaultState.hotkeys.sceneSwitch['Final Stats']`; `BROWSER_SOURCES` URL seeding;
optional preflight warn when `playerStats` empty; shared `DEFAULT_SCENES` from item 8; CHANGELOG +
migration doc note (re-import or manual scene add).

### 16. Tasteful animation pass
Producers like the existing motion. Additions (leaf-only, respecting the documented idle rules):
- map-pool: staggered card entrance (`slideUp`+`delay-*` pattern) on first render only (render-key
  guard already prevents replays).
- lower-third: `.v2-idle-breathe` on the logo leaf (currently the only content overlay with zero idle).
- final-stats: idle-breathe team logos + a one-shot count-up on the totals row at entrance.
- gameplay-hud score boxes: reuse the existing score-pop on diff (already there) — no change.
- Ban Reveal: subtle `.v2-idle-glow` on the BANNED chip. Nothing else — restraint is the feature.
